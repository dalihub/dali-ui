# 16. Lottie: PixelArea

LottieAnimationView의 PixelArea 설정 및 애니메이션 동작을 확인한다.

## 화면 구성

- 중앙: Lottie 애니메이션 프리뷰 (240x240) — 진입 시 자동 재생
- 상태 라벨: `PixelArea: x=.. y=.. w=.. h=..  [태그]` (100ms 폴)
  - 평소에는 `GetPixelArea()` 반환값 — Set→Get 왕복 그 자체다
  - 애니메이션 중에는 뷰의 **현재 애니메이션 값**(GetCurrentProperty)과 `[anim]` 태그 —
    `GetPixelArea()`는 설정값을 보고하므로 애니메이션을 따라가지 않는다(실측)
- 버튼 행 1: Play / Stop (로티 재생 제어 — 프리셋 픽셀 비교용)
- 버튼 행 2: FULL / TOP-L / TOP-R / BOT-L / BOT-R / CENTER (영역 프리셋)
- 버튼 행 3: ANIMATE PIXEL AREA

## 테스트 1: PixelArea 프리셋 왕복

각 프리셋 버튼을 탭할 때마다 라벨이 해당 좌표를 보여야 한다 (getter 반환값):

| 버튼 | 기대 라벨 좌표 |
|---|---|
| FULL | x=0.00 y=0.00 w=1.00 h=1.00 |
| TOP-L | x=0.00 y=0.00 w=0.50 h=0.50 |
| TOP-R | x=0.50 y=0.00 w=0.50 h=0.50 |
| BOT-L | x=0.00 y=0.50 w=0.50 h=0.50 |
| BOT-R | x=0.50 y=0.50 w=0.50 h=0.50 |
| CENTER | x=0.25 y=0.25 w=0.50 h=0.50 |

## 테스트 2: 프리셋 클리핑 (픽셀)

1. [Stop] 버튼으로 로티 재생을 멈춘다 (정지 프레임에서 비교해야 클리핑만 남는다)
2. 프리셋 6개를 차례로 탭하며 각각의 프리뷰를 캡처한다
3. **기대 결과**: 6장이 **서로 전부 달라야** 한다 — "전체냐 아니냐"만 구분하는 구현은
   TOP-L과 BOT-R이 같게 나와 여기서 걸린다
4. [FULL]로 돌아온 캡처는 처음 [FULL] 캡처와 같아야 한다 (복원)

## 테스트 3: PixelArea 애니메이션

1. [ANIMATE PIXEL AREA] 버튼을 탭한다
2. **기대 결과**: 버튼 색상이 바뀌고, 라벨에 `[anim]` 태그와 함께 좌표 값이 3초 동안
   **FULL → TOP-L → CENTER → BOT-R → FULL** 경로를 따라 변한다 (일회성, 순환 아님)
3. **기대 결과**: 3초 뒤 애니메이션이 끝나면 라벨이 `x=0.00 y=0.00 w=1.00 h=1.00  [FULL]`
4. 프리셋(예: CENTER)을 탭하고 [ANIMATE PIXEL AREA]를 탭한 뒤, 끝나기 전에 다시 탭한다
5. **기대 결과**: 애니메이션이 정지하고 직전 프리셋 값으로 복원된다 (라벨 `[CENTER]`)

## 통과 기준

- SetPixelArea 후 GetPixelArea가 동일한 값을 반환해야 한다 (라벨이 getter를 출력)
- 각 프리셋이 해당 영역만 표시해야 한다 (정지 상태에서 6장 캡처가 전부 서로 다름 + FULL 복원 동일)
- 애니메이션 중 관측되는 좌표 값이 여러 개이고 정의된 경로 순서를 따라야 하며, 종료 시 FULL이어야 한다
- 애니메이션 중간 정지 시 직전 프리셋 값으로 복원되어야 한다

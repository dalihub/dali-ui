# 34. InputField Focus

InputField의 탭/롱프레스 포커스 획득 및 ESC 키로 포커스 해제가 정상 동작하는지 확인한다.

**포커스 색은 주황이 아니다.** 휴지 `#FFFFFF` → 포커스 **`#FFF3E0`**(거의 흰색에 가까운
크림색, 채널 편차 0/12/31)라 **육안 판정이 사실상 어렵다** — 기계 판정(픽셀 비교)에는
충분하지만 사람 눈으로 확인할 때는 두 필드를 나란히 비교할 것. (색은 회귀 테스트에 충분해
바꾸지 않기로 결정 — 2026-08-26.)

**ESC 주의 셋** (실측):
- ESC는 **포커스를 가진 InputField가 소비할 때만** 안전하다. **포커스가 없으면 셸이 ESC를
  받아 앱을 종료시킨다** — 두 번 누르지 말 것. (셸 동작은 바꾸지 않기로 결정 — 테스트는
  ESC 후 앱 생존을 함께 단언한다.)
- 에뮬레이터의 **물리 키보드 ESC는 BACK으로 전달될 수 있어**(이전 화면으로) 주입 ESC와
  다르게 동작할 수 있다 — 사람이 수동 실행할 때의 환경 주의.

두 필드에는 automation id가 있다(`Field 1`/`Field 2`) — 접근성 이름이 곧 내용이라 입력 전
선택자가 입력 후 안 맞는 문제의 해법.

## 화면 구성

- 상단: 현재 포커스 상태를 표시하는 라벨 (`FocusManager::FocusChangedSignal` 핸들러가 씀)
- 중앙: 2개의 InputField (플레이스홀더 `Type here...` / `Or here...`, testid `Field 1`/`Field 2`)
- 포커스를 받은 InputField는 배경이 `#FFF3E0`으로 변경됨

## 테스트 1: 탭으로 포커스 획득

1. Field 1을 탭한다
2. **기대 결과**: Field 1 배경이 `#FFF3E0`으로 변경, 상단에 "Focused: Field 1" 표시
3. Field 2를 탭한다
4. **기대 결과**: Field 1 배경 `#FFFFFF` 복귀, Field 2 `#FFF3E0`, 상단 "Focused: Field 2"

## 테스트 2: 롱프레스로 포커스 획득

1. (포커스 없는 상태에서) Field 1을 1초간 길게 누른다
2. **기대 결과**: 포커스 획득 — "Focused: Field 1" (텍스트 컨트롤이라 선택 팝업이 함께 뜰
   수 있다; 판정 대상은 포커스뿐)

## 테스트 3: 텍스트 입력과 유지

1. Field 1을 탭하고 텍스트를 입력한다
2. **기대 결과**: Field 1에 텍스트 표시
3. Field 2를 탭하고 새 텍스트를 입력한다
4. **기대 결과**: Field 1의 텍스트 유지, Field 2에 새 텍스트

## 테스트 4: ESC로 포커스 해제 (선행 조건 필수)

1. Field 1을 탭해 **포커스가 있음을 확인한 뒤** ESC 키를 누른다
2. **기대 결과**: 상단에 **"Focused: (none)"** 표시(라벨은 원인을 단정하지 않는다 — 모든
   포커스 소멸 전환에 같은 문구가 뜬다; ESC가 원인이라는 근거는 단계 순서다), 양쪽 Field
   모두 원래 배경색, **앱은 계속 떠 있어야 한다**
3. ESC를 다시 누르지 않는다 (포커스가 없으므로 앱이 종료된다)

## 통과 기준

- 탭으로 InputField에 포커스를 줄 수 있어야 한다
- 롱프레스로도 포커스를 줄 수 있어야 한다
- 텍스트가 포커스 이동을 넘어 유지되어야 한다
- ESC 키로 포커스가 해제되어야 하며(트리에서도 포커스 노드 0), 그때 앱이 종료되면 안 된다
- 포커스 상태가 배경색(`#FFFFFF`↔`#FFF3E0`)에 반영되어야 한다 — 두 값은 골든 한 장으로
  고정한다 (포커스 색이 조용히 바뀌는 회귀 방지)
- FocusChangedSignal로 포커스 변경이 정확히 통지되어야 한다 (상단 라벨이 그 핸들러의 출력)

("키보드(IME) 활성화"는 다른 프로세스의 창이라 접근성 트리에 나오지 않아 자동 판정 대상이
아니다 — 육안 확인으로 남긴다.)

# 24. ImageView N-Patch Border

NPatchBorder 크기 조절 및 BorderOnly 렌더링 동작을 확인한다.

소재는 `heartsframe.9.png`(249x169, 가이드선 제거 후 247x167; 자동 감지 보더
좌31/우30/상31/하30)다 — 귀퉁이 하트가 커서 "귀퉁이가 고정되는가"가 눈과 픽셀 양쪽으로
판정된다(구 소재 23x27은 판정 불가, 2026-08-26 소재 교체). 수동 보더 전용으로 가이드선을
잘라낸 평면 사본 `heartsframe-plain.png`가 함께 있다 — **수동 BORDER는 평면 이미지용**이다:
`.9.png`에 수동 보더를 걸면 1px 가이드선이 잘리지 않고 그림의 일부로 그려진다(상류
dali-toolkit과 동일 동작; 명세가 `.9.png`에 겹쳐 쓰라고 시켰던 것이 오류였다 — F23).

크기 4종은 모두 늘림 구간이 양수로 유지된다(가로 >61, 세로 >61). 수동 보더 값은 액자
두께(약 25~26px) 이하이고 자동값(31/30)과 **달라야** 오버라이드가 증명된다 — (30)을 쓰면
Auto와 같은 그림이 나와 아무것도 증명하지 못한다.

## 화면 구성

- 중앙: N-Patch 이미지 프리뷰 (회색 배경 위) — 접근성 이름 `ImagePreview`
- 상태 라벨: `Img: <소재> | Size: WxH | Border: … | BorderOnly: …` — Size는
  `GetRequestedWidth()/GetRequestedHeight()`, Border는 `GetNPatchBorder()`, BorderOnly는
  `IsNPatchBorderOnly()` (전부 진짜 getter)
- 버튼 행 1: 120x90 / 250x170 / 400x200 / 560x260
- 버튼 행 2: BorderOnly ON / BorderOnly OFF
- 버튼 행 3: Border Auto / Border (20) / Border (30,20)
- 버튼 행 4: heartsframe.9.png / heartsframe-plain.png / button-up-1.9.png

## 테스트 1: 크기 변경 시 귀퉁이 유지

1. 기준 [250x170](원본 크기) 상태를 확인한다
2. [400x200] → [560x260] 순서로 탭한다
3. **기대 결과**: **네 귀퉁이의 하트 그림이 원본 이상 세 크기(250/400/560)에서 모두
   동일**하고(늘어나지 않음), 중앙과 변 구간만 늘어난다. `Size:` 라벨이 각 값 그대로
4. [120x90] 버튼을 탭한다
5. **기대 결과**: **원본(247x167)보다 작은 크기에서는 코너까지 전체가 비례 축소**된다 —
   9-patch의 표준 sub-natural 동작(실측 2026-08-26; Android 9-patch도 동일). 코너 고정
   기준은 원본 이상 크기에만 적용된다

## 테스트 2: BorderOnly 모드 (수동 보더에서)

1. **[Border: (20)]을 먼저** 탭한다 — auto 보더(0벡터) 상태의 BorderOnly는 알려진 결함
   F20으로 무효라, 수정 전까지 이 절차는 수동 보더에서 확인한다
2. [BorderOnly ON] 버튼을 탭한다
3. **기대 결과**: 중앙이 **프리뷰 배경색(회색 0x444444)으로 드러나고** 보더 띠만 렌더된다.
   뚫린 구멍의 위치가 지정한 보더 값과 픽셀 단위로 일치한다 (실측: (30,20)→좌30 우20 상30
   하20 정확)
4. [BorderOnly OFF] 버튼을 탭한다
5. **기대 결과**: 전체 이미지가 다시 표시됨 (ON 이전과 동일)

## 테스트 3: 수동 Border 설정 (평면 소재에서)

1. [heartsframe-plain.png] 버튼을 탭한다 — 수동 보더는 평면 이미지용
2. [Border: (20)] 버튼을 탭한다
3. **기대 결과**: `Border: (20,20,20,20)` (getter), 렌더가 Auto 상태와 달라짐 (실측 3.36%+)
4. [Border: (30,20)] 버튼을 탭한다
5. **기대 결과**: `Border: (30,20,30,20)`, 렌더가 (20)과도 달라짐

> **F21 주의 (수정 전까지)**: 수동 보더를 건 뒤 [Border: Auto]를 눌러도 auto 렌더로
> 복원되지 않으며 되돌릴 수단이 없다(라벨은 `auto`로 맞는데 그림은 균일 늘리기 그대로).
> 소재를 바꿨다 돌아오거나 화면을 나갔다 오면 풀린다. 자동 복원 검증은 결함 수정 후
> "같은 크기·같은 라벨이면 첫 캡처와 비트 동일"로 되살린다.

## 통과 기준

- 원본 이상 크기(250/400/560)에서 네 귀퉁이 그림이 모두 동일해야 한다 (보더 고정);
  원본 미만(120x90)은 전체 비례 축소가 정상이다
- BorderOnly ON 시 중앙이 프리뷰 배경색으로 드러나고, 구멍 위치가 보더 값과 일치해야 한다
- 수동 보더가 렌더에 실제 반영되고(Auto와 상이), 값이 getter로 왕복해야 한다
- `Img:` / `Size:` / `Border:` / `BorderOnly:` 라벨(전부 getter)이 설정값과 일치해야 한다

> **알려진 컴포넌트 결함 (이슈 리포트 대상, 3.8 막힘 유지)**
> - **F20**: auto 보더(0벡터)에서 `SetNPatchBorderOnly(true)`가 무효 — `BORDER_ONLY`를
>   속성 맵에 넣는 줄이 `if(mNPatchBorder != Vector4::ZERO)` 안에 있다
> - **F21**: 수동 보더 뒤 `Border: Auto`(0벡터)가 복원되지 않음 — 같은 URL·다른 보더
>   조회가 기존 텍스처 재사용 경로에서 늘림 구간을 요청 보더(0=전체 늘리기)로 재계산
> - 뿌리는 하나: **"자동"을 0으로 표현해 놓고 한 곳은 "설정 안 함", 한 곳은 "크기 0"으로
>   읽는다**

# 29. Focus Navigation

방향키를 이용한 포커스 네비게이션이 정상 동작하는지 확인한다.

## 화면 구성

- 상단: 현재 포커스 상태를 표시하는 라벨
- 하단: 2x2 그리드로 배치된 4개의 View
- View 1 기본색은 분홍색(`#E8D5E0`), View 2 기본색은 연녹색(`#D5E0D8`), View 3 기본색은 파란색(`#D5DBE8`), View 4 기본색은 베이지색(`#E0D8D5`)
- 포커스를 받은 View는 주황색(`#FF9800`)으로 변경됨

```
  [View 1] [View 2]
  [View 3] [View 4]
```

## 테스트 1: 방향키 포커스 이동

1. View 1에 포커스를 둔 상태에서 → (Right) 키를 누른다
2. **기대 결과**: View 2로 포커스 이동
3. ↓ (Down) 키를 누른다
4. **기대 결과**: View 4로 포커스 이동
5. ← (Left) 키를 누른다
6. **기대 결과**: View 3으로 포커스 이동
7. ↑ (Up) 키를 누른다
8. **기대 결과**: View 1으로 포커스 이동

## 테스트 2: 포커스 인디케이터

**화면 진입 직후에는 인디케이터가 없다** — 진입 시 포커스는 프로그램이 준 것이고,
인디케이터는 키보드/게임패드/휠 입력에만 그려진다(`ShouldIndicateFocus()`). 진입 화면에서
"주황인데 테두리가 없다"는 오탐이 아니라 사양이다.

1. 진입 직후(키 입력 전) View 1의 모습을 기억해 둔다 — 주황 배경, 테두리 없음
2. 방향키로 한 바퀴(→↓←↑) 돌아 View 1로 돌아온다
3. **기대 결과**: 같은 칸·같은 포커스·같은 주황인데 **3px 인디케이터 테두리가 더해져**
   진입 직후와 다르게 보인다 (실측: 5.05~5.22% 픽셀 차이, 전부 테두리 영역, 완전 대비)

## 통과 기준

- 방향키로 2x2 그리드 내 상하좌우 이동이 가능해야 한다 (배선 8개 전부)
- 포커스를 가진 View만 주황색(`#FF9800`)으로 표시되어야 한다 — 네 칸의 색 전부를 한 장으로
  고정한다 (그리드 전체 골든: 포커스 칸 `#FF9800` + 나머지 세 칸 각자의 휴지색; 포커스 색을
  빨강으로 바꾸는 회귀는 "달라졌다" 검사로는 통과하므로 값 고정이 필요하다)
- 키 입력 후의 포커스 칸에는 인디케이터 테두리가 표시되어야 한다 (진입 직후와의 격리 비교)
- 상단 라벨에 현재 포커스된 View 번호가 정확히 표시되어야 한다

# 158. AnimatedImageView: duplicate URL cache

이 테스트는 같은 PNG 파일을 여러 프레임에서 사용하는 `AnimatedImageView`의 로딩, 캐시 교체, 재생 제어를 눈으로 확인하기 위한 것이다. `dali-ui-foundation` manual test 런처에서 **158. AnimatedImageView: duplicate URL cache**를 선택한다.

## 화면 구성

- **1-2-3-1-2-3**: 세 PNG를 순서대로 두 번 나열한다. 같은 URL이 떨어져 있는 경우다.
- **1-1-2-2-3-3**: 각 PNG를 연속으로 두 번 나열한다. 같은 URL의 로드 결과가 연속 프레임에 전달되는 경우다.
- **Batch size / Cache size**: 각각 1부터 6까지의 슬라이더다. 값을 탭하거나 드래그하면 현재 뷰를 `Unparent()`하고 `Reset()`한 다음, 1초 뒤 새 뷰를 추가한다. 순서 버튼을 바꿔도 같은 절차를 수행한다. 1초 사이에 다시 변경하면 마지막 설정으로 타이머를 재시작한다.
- **Play automatically after re-add**: 기본은 꺼짐이다. 켜면 1초 뒤 새 뷰가 추가될 때 `Play()`를 호출한다. 끄면 추가 직후 상태와 첫 프레임을 관찰한 후 Play를 직접 누른다.
- **Play / Pause / Stop**: 현재 뷰의 재생을 제어한다. 상태 표시에는 순서, 두 크기, 재생 상태, 현재 프레임과 총 프레임 수가 나온다.

`ReleasePolicy::DETACHED`를 설정하고 뷰를 실제로 파괴하므로 이전 뷰가 보유한 프레임 캐시와 observer는 재추가 전에 해제된다. TextureManager 내부의 공유 텍스처나 다른 뷰가 보유한 항목까지 이 화면만으로 비었다고 증명할 수는 없다.

## 확인 절차

1. 기본 순서로 **Play**를 누른다. 표시 프레임이 0부터 5까지 반복되고 이미지가 계속 바뀌는지 확인한다.
2. **1-1-2-2-3-3**을 선택한다. 화면에서 이미지가 1초간 사라졌다가 돌아오는지 확인한다. 자동 재생이 꺼져 있으면 `STOPPED` 상태인지 확인한 뒤 **Play**를 누른다. 같은 이미지가 두 프레임씩 유지되며 0~5 프레임이 계속 순환해야 한다.
3. 각 슬라이더를 1부터 6까지 바꿔 본다. 매 변경 때 1초간 비워지고 새 설정으로 로드되어야 한다. 특히 **Batch 6 / Cache 6**과 **Batch 2 / Cache 2**를 두 순서 모두에서 확인한다. 프레임이 멈추거나 재생 타이머가 종료되면 실패다.
4. **Pause**를 누르면 프레임 번호가 멈추고, **Play**를 누르면 다시 진행하는지 확인한다. **Stop**을 누르면 `STOPPED` 상태로 바뀌는지 확인한다.
5. 자동 재생을 켜고 슬라이더나 순서를 바꾼다. 1초 뒤 뷰가 다시 추가되면 별도 Play 없이 `PLAYING`이 되고 프레임이 진행해야 한다. 자동 재생을 끄고 다시 변경하면 새 뷰의 기본 재생 상태를 확인할 수 있다.

이 manual test는 화면 동작을 확인하는 용도다. 자동 UTC는 `utc-Dali-AnimatedImageView.cpp`에서 중복 URL의 고정/롤링 캐시와 큰 GIF 캐시를 별도로 검증한다.

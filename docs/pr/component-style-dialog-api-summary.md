## 제목

컴포넌트 스타일 및 Dialog API 일관성 개선

## 배경 및 목적

`dali-ui-components`의 컴포넌트들이 일관된 방식으로 생성·설정될 수 있도록 스타일 API와 상태 처리 방식을 정리합니다.

기존 Dialog 계열은 다른 컴포넌트와 달리 기본 외형을 전용 스타일로 관리하지 않아, 배경·여백·타이포그래피 등의 표현 정책이 구현 코드에 분산되어 있었습니다. 또한 아이콘 크기 생략 시 처리, 스타일 입력값 검증, 모달 콘텐츠 교체와 접근성 상태 복원 등에서 사용자가 동작을 예측하기 어려운 부분이 있었습니다.

이번 변경은 다음을 목표로 합니다.

- 컴포넌트 생성 및 스타일 수정 API의 일관성 확보
- 표현 정책과 인스턴스의 콘텐츠·상태 관리 분리
- 기존 생성 API를 유지하면서 사용자 정의 스타일 지원 확대
- 이미지 로딩 및 모달 수명 변화에서 발생할 수 있는 예외 상황 보완
- 회귀 테스트와 사용 예제를 통해 API 계약 명확화

## 주요 변경 사항

### 1. Dialog 계열에 전용 스타일 도입

다음 세 가지 불변 스타일을 추가했습니다.

| 스타일 | 담당하는 표현 정책 |
|---|---|
| `DialogStyle` | Dialog 자체의 기본 크기, 배경, 전체 여백, 섹션 간격, 모서리, 그림자, 테두리, 블러 |
| `AlertDialogStyle` | 중첩 Dialog 스타일, 제목·본문 타이포그래피, 액션 버튼 스타일 및 액션 영역 배치 |
| `DialogContainerStyle` | 컨테이너가 생성하는 기본 scrim의 색상과 블러 |

기존 스타일과 동일하게 `DefaultKey`, `Default`, `DefaultPreset`, `DownCast`, `StaticDownCast`, `Configure` 및 이동 전용 Builder 패턴을 제공합니다.

- `Default()`는 현재 설정의 스타일을 조회하고, 필요한 경우 내장 기본값으로 대체합니다.
- `DefaultPreset()`은 설정 provider와 독립적인 내장 기본 스타일을 제공합니다.
- `Configure()`는 원본 스타일을 변경하지 않고 수정 가능한 Builder를 반환합니다.
- Builder는 `Build()` 시 소비되며, 빌드된 스타일은 불변 객체로 사용됩니다.
- 새 스타일을 Components 스타일시트와 공개 umbrella 헤더에 연결했습니다.

### 2. 기존 생성 API 유지 및 스타일 적용 경로 정리

기존 무인자 생성 API를 유지하면서 스타일을 직접 지정하는 경로를 추가했습니다.

- `Dialog::New()` / `Dialog::New(DialogStyle)`
- `AlertDialog::New()` / `AlertDialog::New(AlertDialogStyle)`
- `DialogContainer::New()` / `DialogContainer::New(DialogContainerStyle)`

무인자 `New()`는 해당 컴포넌트의 기본 스타일을 사용하는 경로로 연결됩니다.

Dialog의 표현 설정은 스타일에서 가져오되, 제목·본문·액션·섹션 View와 같은 콘텐츠는 기존처럼 인스턴스 API로 관리합니다. 스타일 객체가 콘텐츠나 모달 상태를 소유하지 않도록 역할을 분리했습니다.

### 3. 사용자 지정 속성 보존

스타일 도입으로 기존 사용자 설정이 불필요하게 덮어써지지 않도록 적용 조건을 정리했습니다.

- Header·Body·Footer로 전달하는 View의 padding과 외형은 호출자가 직접 설정합니다. DialogStyle에는 섹션별 padding 설정·조회·초기화 API를 두지 않습니다.
- 섹션 부착·교체·제거·재부착 시 자식 View의 padding과 외형을 보존합니다. 명시적 0도 그대로 유지하며, Dialog는 자체 여백과 섹션 간격·배치를 관리합니다.
- AlertDialog의 제목·본문 변경 시 기존 Label을 재사용해 사용자가 지정한 속성을 보존합니다.
- 중첩 스타일이 비어 있는 경우에는 정의된 기본 스타일로 대체합니다.
- 사용자 제공 scrim의 외형은 보존하고, `DialogContainerStyle`은 컨테이너가 생성하는 기본 scrim에 적용합니다.

다만 custom scrim의 크기와 쌓임 순서는 컨테이너가 관리합니다. 또한 scrim 클릭은 신호를 전달하는 동작이며, 자동 닫기나 포커스 이동 정책은 애플리케이션에서 결정합니다.

### 4. IconButton 크기 결정 및 재측정 개선

아이콘 크기가 생략된 경우 이미지의 실제 크기를 활용하도록 크기 결정 규칙을 정리했습니다.

**명시한 크기 → 유효한 이미지 natural size → 기본값 56**

- 명시적인 크기와 레이아웃 sentinel의 의미를 유지합니다.
- 명시적 `0`은 크기 미지정과 구분합니다.
- 한 축만 고정되고 유효한 natural size가 있으면 이미지 비율을 반영합니다.
- 이미지가 아직 준비되지 않았거나 유효한 natural size를 제공하지 못하면 기본 크기를 사용합니다.
- 비동기 이미지 로딩 완료 시 측정을 무효화해 최종 이미지 크기를 다시 반영합니다.
- `IconButtonStyle::Configure()` 경로에서도 기존 설정값이 보존되도록 보완했습니다.

### 5. 스타일 입력값 검증 정리

스타일에서 사용하는 크기·여백·반경 등의 검증 로직을 공통 헬퍼로 정리했습니다.

- 음수, 비유한 값 및 허용되지 않는 레이아웃 값을 검증합니다.
- TextButton의 최소·최대 크기 관계는 최종 `Build()`에서 확인해 setter 호출 순서에 따른 불필요한 제약을 줄였습니다.
- 블러 반경의 허용 범위와 적용 시 소수 부분 처리 정책을 명확히 했습니다.
- IconButton, CheckBox, RadioButton의 `0` 및 미지정 값 의미처럼 컴포넌트별로 필요한 차이는 유지했습니다.

모든 컴포넌트를 동일한 수치 처리 방식으로 강제하기보다, 공통 검증 방식과 컴포넌트별 계약을 구분하는 데 초점을 맞췄습니다.

### 6. 모달 수명 및 접근성 상태 처리 보강

DialogContainer의 콘텐츠 교체·제거·재부모화 과정에서 모달 상태와 소유권이 어긋나지 않도록 보완했습니다.

- 모달 콘텐츠가 다른 컨테이너로 이전될 때 이전 소유자의 상태를 정리합니다.
- 제거·이전·컨테이너 해제 시 원래의 명시적 모달 플래그를 복원합니다.
- 콜백 실행 중 콘텐츠가 다시 변경되는 재진입 상황을 고려합니다.
- 표시 상태 변화에 따른 접근성 `SHOWING` 알림 처리를 보강했습니다.
- scrim 교체 시 기존 클릭 연결을 해제해 오래된 콜백이 남지 않도록 했습니다.
- 관련 버튼 컴포넌트의 비활성 상태와 접근성 상태 동기화를 보완했습니다.

Foundation·Adaptor 제품 코드는 이번 커밋에 포함하지 않습니다.

### 7. 테스트 및 사용 가이드 보완

다음 영역의 회귀 UTC를 추가했습니다.

- 스타일 기본값, 복제, Builder 소비 및 입력값 검증
- 명시적 아이콘 크기, natural size 및 fallback 처리
- Dialog 스타일 적용과 사용자 지정 속성 보존
- 모달 콘텐츠 교체·이전·제거 및 재진입 처리
- 접근성 상태와 이벤트 처리

추가로 선택적 AT-SPI 이벤트 검증 타깃을 제공했습니다. 이 타깃은 이벤트 전달 경로를 검증하기 위한 것으로, 실제 데스크톱 스크린리더의 종단 간 검증을 대체하지 않습니다.

Release에서 공개되지 않는 내부 생성자에 대한 UTC 의존성을 제거했습니다. AlertDialog 파생 클래스는 공개 `CustomActor` 생성자와 `DownCast()`를 사용하고, scrim의 blur는 실제 타입을 확인한 뒤 공개 핸들 대입으로 반경을 검증합니다. 공통 Scene 테스트 유틸리티도 공개 기본 생성자로 빈 핸들을 초기화합니다. 제품 API나 심볼 공개 설정은 변경하지 않았습니다.

샘플 README, 수동 테스트 시나리오 및 Wiki에는 생성·설정 순서, 스타일 수정 방법과 상태 소유권을 설명했습니다. 신규 네임스페이스 선언은 `DALI_NAMESPACE`를 사용하고, 변경 범위의 코드 주석은 영어로 정리했습니다.

영문·한국어 Components 위키 목록에 신규·변경 컴포넌트의 설명과 가이드·공개 API·샘플 링크를 보완하고, 한국어 홈에서도 한국어 목록으로 연결했습니다.

## 호환성 및 검토 시 주의사항

- 기존 무인자 `New()`를 유지합니다.
- 스타일은 생성 시 표현 정책이며, 전체 런타임 스타일 교체 API를 추가한 것은 아닙니다.
- 상속된 모든 View 속성의 사용자 override가 영구적으로 보존된다는 계약은 아닙니다. 컨테이너가 관리하는 크기·배치 등은 별도의 소유권 규칙을 따릅니다.
- 잘못된 수치 입력은 검증 대상이므로, 기존에 허용되지 않는 값을 전달하던 호출부는 확인이 필요합니다.
- Foundation·Adaptor 변경, AI-SDLC·Superpowers 관련 문서 및 빌드 산출물은 포함하지 않습니다.

## 검증 결과

| 대상 | 결과 |
|---|---|
| Release UI 라이브러리 전체 | 섹션 스타일 제거 후 재빌드·설치 통과 |
| 샘플 실행 파일 | 섹션 스타일 제거 후 170개 재링크를 포함한 빌드 통과 |
| 수동 테스트 앱 | 섹션 스타일 제거 후 3종 타깃 빌드 통과 |
| `video-view` 샘플 | Tizen 미디어 패키지 부재로 CMake에서 제외 |
| Components·Foundation 기본 UTC 타깃 | 내부 생성자 의존성 수정 후 Release 빌드 및 최종 링크 통과 |
| Dialog·DialogContainer·AlertDialog UTC | 75개 실행 통과, 실패 0개 |
| Foundation-internal·선택적 AT-SPI 타깃 | 이전 검증에서 소스 컴파일 통과, 최종 링크 실패; 이번 수정 후 재검증하지 않음 |

Dialog 관련 UTC는 사용자 D-Bus 세션과 설정에 연결되지 않도록 격리한 환경에서 테스트 실행 파일을 직접 실행했습니다. `execute.sh`와 GUI 테스트는 실행하지 않았습니다.

**UTC 전체 통과를 주장하지 않습니다.** Foundation-internal과 선택적 AT-SPI 타깃은 기존 로그에 Core의 Debug 로그 함수 및 Adaptor의 DBus 내부 심볼 관련 링크 오류가 남아 있어 별도 검증이 필요합니다. Components·Foundation 기본 UTC의 빌드는 제품 라이브러리의 Release 심볼 공개 정책을 유지한 상태에서 확인했습니다.

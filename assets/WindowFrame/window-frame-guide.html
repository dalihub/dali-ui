02 · DEFAULT DECORATION

기본 창 장식으로 바로 시작하기

직접 decoration을 만들기 전에, 완성된 창 장식을 먼저 붙여 보십시오. DefaultWindowDecoration는 decoration, layout, style을 만들고 설치한 뒤 창 상태에 맞춰 유지까지 합니다.

#include <dali-ui-components/public-api/window/default-window-decoration.h>

// shadow가 frame 바깥 surface에 그려지므로 창은 투명해야 합니다.
window.SetBackgroundColor(Color::TRANSPARENT);
window.SetTransparency(true);

mWindowFrame  = WindowFrame::New(window, closeCallback);
mDefaultDecoration = DefaultWindowDecoration::New(mWindowFrame);   // 기본 창 장식
mWindowFrame.Attach();

mWindowFrame.GetContentRoot().Add(myContent);
mDefaultDecoration handle을 멤버로 보관하십시오앱 action callback과 window 상태를 따라가는 연결을 이 handle이 소유합니다. 해제해도 WindowFrame이 소유한 decoration은 계속 그려지고 기본 minimize/maximize/close도 동작하지만, AddBarAction() callback과 maximize 아이콘·corner radius의 상태 동기화는 멈춥니다.
기본 하단 bar 배치왼쪽부터 bottom-left resize handle, 남은 폭을 채우는 move region, 앱 action, 기본 제공 minimize, maximize/restore, close 버튼, bottom-right resize handle 순서입니다. 여기서 기본 버튼 셋을 window controls라고 부릅니다.
상단 영역과 앱 액션기본 창 장식을 그대로 쓰면서 두 가지를 더할 수 있습니다. DefaultWindowDecorationOptions::SetTopAreaHeight()는 얇은 상단 테두리를 앱이 채우는 영역으로 바꾸고 GetTopArea()로 돌려줍니다. GetMoveRegion()은 하단 bar에서 남은 폭을 차지하며 title이나 branding을 넣을 수 있습니다. AddBarAction(iconUrl, onClick)은 move region과 기본 제공 minimize, maximize/restore, close 버튼 사이에 자기 컬럼을 잡아 버튼을 넣습니다. Top area와 앱 action은 move region이 아니므로 최대화 상태에서도 눌립니다. iconUrl에는 앱 resource의 full URL을 전달하며 앱 아이콘에는 theme tint가 적용되지 않습니다. 액션 추가 후 커진 GetMinimumFrameSize()를 다시 적용하십시오.
DefaultWindowDecorationOptions options;
options.SetTopAreaHeight(44.0f);
mDefaultDecoration = DefaultWindowDecoration::New(mWindowFrame, options);
mDefaultDecoration.GetTopArea().Add(myBranding);

const Dali::String iconUrl = Dali::String(RESOURCES_DIR) + "share.png";
mDefaultDecoration.AddBarAction(
  iconUrl, Dali::Callback<void()>::New(this, &App::Share));
mWindowFrame.SetMinimumFrameSize(mDefaultDecoration.GetMinimumFrameSize());
최소 크기는 물어보십시오바는 컨트롤과 코너 리사이즈 핸들마다 고정 폭 열을 잡습니다. 그보다 좁아지면 move region 폭이 0이 되고 close 버튼이 코너 핸들 밑으로 들어갑니다. mWindowFrame.SetMinimumFrameSize(mDefaultDecoration.GetMinimumFrameSize())로 적용하십시오. 기본 옵션에서는 276 x 55이고, 컨트롤이나 핸들을 끄면 줄어듭니다. 창의 크기 제약은 앱의 몫이므로 decoration이 스스로 적용하지는 않습니다.

무엇이 만들어지는가

Bottom bar

minimize, maximize/restore, close가 오른쪽에 놓이고 남은 영역 전체가 move region입니다.

Top / Left / Right edge

같은 두께의 얇은 edge로 frame을 사방에서 감쌉니다.

Bottom corner handle

양쪽 하단 코너에 명시적 resize handle을 놓습니다. 8방향 hit region은 없습니다.

칠하는 것은 decoration뿐입니다frame 배경은 투명하므로 앱이 그리는 영역에는 색이 입혀지지 않고, 투명한 창은 앱이 그리지 않은 곳에서 계속 비쳐 보입니다. frame은 cut-out shadow를 그리는데, cut-out이 없으면 투명한 frame 때문에 blur가 content 영역까지 어둡게 만듭니다.

어디까지 바꿀 수 있는가

GetMoveRegion()

bottom bar의 move region을 반환합니다. 입력이 필요 없는 제목이나 branding을 넣을 수 있습니다. 최대화 중에도 눌려야 하는 아이콘은 AddBarAction(), 자유로운 interactive content는 GetTopArea()를 사용합니다.

GetDecoration()

설치된 WindowFrameDecoration의 복사본입니다. 같은 view handle을 들고 있으므로 view의 property를 바꾸면 설치된 보더가 바뀝니다. slot이나 role에 다른 view를 대입하는 것은 복사본만 고치므로, 교체하려면 그 복사본을 SetDecoration()으로 다시 설치해야 합니다.

직접 만들기

모양을 통째로 바꿀 것이라면 아래 03~06 절대로 WindowFrameDecoration을 만들어 SetDecoration()으로 설치합니다. handle은 먼저 해제합니다.

아이콘 자산아이콘은 컴포넌트와 함께 <dataReadOnlyDir>/ui/images/components/border/에 설치됩니다. 기본 리소스 디렉터리를 쓰지 않는 빌드는 DALI_UI_COMPONENTS_IMAGE_DIR 환경 변수로 경로를 찾습니다. 알파 채널을 가진 흰색 glyph라 한 세트가 두 theme를 모두 처리합니다.
03 · ARCHITECTURE

무엇을 만들고, 누가 무엇을 소유하는가

WindowFrame은 새 native window가 아니라 기존 Dali::Window를 꾸미고 제어하는 facade입니다.

Application / 3rd party제품 UI와 정책
ProductDesktopWindow선택 계층: virtual factory, typed hook, 앱 친화 API
Dali::Ui::WindowFramelayout, role input, overlay, state, geometry의 공통 구현
Decoration Views + Content View앱이 제공하는 top/bottom/side/role과 실제 화면
Dali::Window / compositornative surface, maximize/restore geometry, move/resize 완료
가장 중요한 사용 계약 앱 content는 root layer에 직접 넣지 않고 mWindowFrame.GetContentRoot().Add(appContent)로 추가합니다. 그러면 border와 shadow 크기를 앱 좌표 계산에서 직접 빼지 않아도 됩니다.

WindowFrame이 담당

frame/content layout, role 입력 연결, overlay, operation/state signal, size constraint

Compositor가 담당

일반 maximize 이후 restore 위치와 크기, native move/resize의 실제 geometry와 완료

제품 wrapper가 담당

브랜드 UI, button 구성, command 전처리, 앱 상태 후처리, product-specific policy

04 · ACTOR & LAYOUT

Frame 안의 View 구조

slot은 보이는 영역이고 role은 동작을 지정합니다. SetMoveRegion()과 세 Set...Control() API는 새 layout 영역을 만들지 않고 slot tree 안의 View에 동작만 부여합니다. 여기서 control은 일반적인 window title bar의 최소화, 최대화/복원, 종료 버튼 역할을 뜻합니다.

샘플의 bottom 역할 배치

[left resize 36] [move *] [min 40] [max 40] [close 40] [right resize 36]

  • top/bottom/left/right slot root는 설치 전에 parent가 없어야 합니다.
  • move/minimize/maximize/close role은 네 slot 중 하나의 자손이어야 합니다.
  • bottom resize handle은 독립 slot이자 role이므로 unparented View로 전달합니다.
  • 이미 이 WindowFrame에 설치되어 있는 slot은 그대로 다시 제출할 수 있습니다. 새 layout나 style과 함께 재설치할 때 view를 다시 만들 필요가 없습니다. 다른 부모가 소유한 slot은 계속 SLOT_ALREADY_PARENTED로 거부됩니다.
  • 동일 View를 서로 다른 command role에 중복 등록하지 않습니다.
Role control에는 click callback을 중복 연결하지 않습니다.Decoration role로 등록하면 WindowFrame이 기본 command를 연결합니다. 앱 callback까지 붙이면 한 번의 입력에서 두 동작이 실행될 수 있습니다.

SetDecorationInsets()

Insets(start, end, top, bottom)

SetDecorationInsets()는 border를 그리는 API가 아니라, frame 내부에서 네 decoration slot이 차지할 공간을 선언합니다. 이 값으로 각 slot의 bounds와 normal mode의 content root 영역을 계산합니다.

start · left8
end · right8
top64
bottom56
WindowFrameLayout layout;
layout.SetDecorationInsets(
  Insets(8.0f, 8.0f, 64.0f, 56.0f));

400 × 260 frame 계산

content width = 400 - 8 - 8 = 384

content height = 260 - 64 - 56 = 140

따라서 샘플 status에 표시되는 content 크기는 384 × 140입니다. 앱 content의 (0, 0)은 이 content root의 좌상단입니다.

Padding, shadow, resize handle 크기와는 다른 값입니다. slot 안쪽 button 간격은 각 slot layout이 정합니다. Shadow 바깥 공간은 SetShadowOutsets(), 두 resize handle 크기는 SetBottomLeftResizeHandleSize()와 SetBottomRightResizeHandleSize()가 담당합니다.

최소 사용 코드 보기 
void MyWindowController::OnInit(Dali::Application app)
{
  mWindow = app.GetWindow();
  mWindow.SetBackgroundColor(Dali::Color::TRANSPARENT);
  mWindow.SetTransparency(true);

  Dali::Ui::WindowFrameOptions options;
  options.SetInitialRestoreFrameSize(Dali::Vector2(400.0f, 260.0f));
  mWindowFrame = Dali::Ui::WindowFrame::New(mWindow, closeCallback, options);
  mWindowFrame.SetOverlayEnabled(true);
  mWindowFrame.SetOverlayAutoHideDelay(2500u);

  Dali::Ui::WindowFrameLayout layout;
  layout.SetDecorationInsets(Dali::Ui::Insets(8.0f, 8.0f, 64.0f, 56.0f));

  const auto result = mWindowFrame.SetDecoration(
    CreateMyDecoration(), layout, CreateMyFrameStyle(),
    Dali::Ui::WindowFrameSizePolicy::KEEP_WINDOW_SIZE);
  if(result != Dali::Ui::WindowFrameDecorationResult::INSTALLED)
  {
    return;
  }

  mWindowFrame.RequestFrameResize(Dali::Vector2(400.0f, 260.0f));
  mWindowFrame.Attach();
  mWindowFrame.SetMinimumFrameSize(Dali::Vector2(200.0f, 130.0f));
  mWindowFrame.GetContentRoot().Add(CreateApplicationContent());
}

검증과 실패는 view를 받는 쪽에만 있습니다slot/role 토폴로지를 검증하는 것은 SetDecoration() 두 형태뿐이고, 확인할 만한 결과를 돌려주는 것도 이 둘뿐입니다. 좁은 setter 두 개는 실패할 수 없습니다. 또 ClearDecoration()은 항상 window 크기를 유지하므로 content root가 장식이 차지하던 공간까지 커집니다.

SetDecoration()

Decoration 검증

slot 중복/parent 여부, role 중복, role이 decoration 밖에 있는지 검사합니다.

Geometry 계산

SetDecorationInsets() 값으로 slot과 content bounds를 다시 계산합니다.

설치 실패

SLOT_ALREADY_PARENTED, DUPLICATE_SLOT, DUPLICATE_ROLE, ROLE_OUTSIDE_DECORATION 등을 반환하고 현재 frame을 유지합니다.

언제 다시 호출하는가? top/bottom 구조, role 배치, insets 또는 frame style을 하나의 새 테마로 바꿀 때 호출합니다. text, color, icon처럼 기존 view property만 바뀌는 경우에는 전체 frame을 다시 설치하지 않고 해당 View를 직접 갱신할 수 있습니다.

교체할 때 유지할 크기 선택

KEEP_CONTENT_SIZE

border 두께나 shadow가 바뀌어도 앱 content 크기를 유지합니다. attached normal 상태에서 native surface를 조정하므로 일반적인 테마 변경에 적합합니다.

KEEP_WINDOW_SIZE

외부에서 결정한 window 크기를 유지합니다. border 변화에 따라 content 크기가 달라질 수 있으며 초기 frame 설치에 적합합니다.

호출별 policy입니다Size policy는 WindowFrame에 저장되어 다음 변경으로 이어지는 설정이 아닙니다. SetDecorationLayout(layout, KEEP_CONTENT_SIZE) 뒤에 SetFrameStyle(style, KEEP_WINDOW_SIZE)를 호출하면 첫 호출은 content를 보존하고, 두 번째 호출은 그 시점의 window surface를 독립적으로 보존합니다. 따라서 두 번째 style의 shadow outsets에 따라 frame과 content 크기는 달라질 수 있습니다.

07 · COMMAND POLICY

DesktopWindow처럼 기본 동작 사이에 정책 넣기

subclass override 대신 command interceptor가 move, resize, minimize, maximize, restore, close 직전의 정책 지점을 제공합니다.

CONTINUE_DEFAULT

제품별 사전 처리를 수행한 뒤 WindowFrame의 기본 native command를 계속합니다. 대부분의 maximize, restore, move, resize 확장은 이 값을 사용합니다.

기본값 · native request와 이후 state/geometry 추적을 WindowFrame이 담당

HANDLED

앱이 command를 넘겨받았으므로 기본 동작을 막습니다. 직접 처리하든, 거절하든, 다른 native API로 자체 동작을 시작하든 모두 여기에 해당합니다. 저장 확인이 필요한 close가 대표적인 예입니다.

기본 native request 없음 · WindowFrame은 이후 아무 것도 추적하지 않음
Interceptor 재귀 진입 금지OnCommand() 안에서 같은 mWindowFrame.RequestMaximize() 같은 API를 다시 호출하지 않습니다. 기본 native 요청을 계속하려면 단순히 CONTINUE_DEFAULT를 반환합니다.

제품별 사전 처리 예제

WindowFrameCommandDisposition OnCommand(
  WindowFrame sender,
  const WindowFrameCommandRequest& request)
{
  if(request.GetCommand() == WindowFrameCommand::MAXIMIZE)
  {
    HideTransientPopup();
  }

  if(request.GetCommand() == WindowFrameCommand::CLOSE &&
     HasUnsavedData())
  {
    ShowSaveConfirmation();
    return WindowFrameCommandDisposition::HANDLED;
  }

  return WindowFrameCommandDisposition::CONTINUE_DEFAULT;
}
08 · CALLBACK TIMING

요청, compositor 확인, 화면 표시를 구분하기

“요청을 보냈다”와 “native 상태가 바뀌었다”, “그 상태가 화면에 보였다”는 서로 다른 시점입니다.

Maximize / restore

Interceptor

앱 정책 적용 또는 default command 허용

COMMAND
DISPATCHED

CommandProcessedSignal · underlying operation 호출까지. 수락도 완료도 아님

DISPATCH
STATE CHANGED

WindowStateChangedSignal · compositor가 native 상태 확정

COMPOSITOR
STATE PRESENTED

WindowStatePresentedSignal · 새로 관찰된 NORMAL/MAXIMIZED 상태가 frame으로 그려짐

FRAME
NUI의 OnMaximize()와 가장 가까운 시점maximize/restore가 실제 frame에 반영된 뒤 후처리하려면 WindowStatePresentedSignal()을 사용합니다. 이 signal은 WindowStateChangedSignal() 뒤에 같은 상태를 실어 보내므로 compositor가 주도한 변경에도 발생합니다. 두 경우에만 발생하지 않습니다. MINIMIZED는 표시할 frame이 없어서, 그리고 frame을 기다리는 동안 더 최신 상태가 도착하면 이전 상태는 건너뜁니다. 내부 frame callback은 signal에 observer가 있을 때만 등록됩니다.
활성화된 명시적 요청은 항상 전달됩니다RequestMinimize(), RequestMaximize(), RequestRestore()는 창이 이미 그 상태로 보이더라도 window system까지 전달됩니다. 걸러내려면 마지막으로 보고된 상태와 비교해야 하는데, 그러면 RequestMaximize() 직후의 RequestRestore()처럼 이전 요청이 보고되기 전에 보낸 요청이 버려집니다. 이미 적용된 요청을 다시 보내는 것은 무해하므로 걸러내지 않습니다. ToggleMaximize()만 예외로, 토글은 자체 목표가 없어 마지막으로 보고된 상태를 읽습니다.

Move / resize

STARTED

role touch down 후 move/resize 요청과 interaction tracking이 시작됐습니다.

CHANGED

compositor가 geometry를 바꾸는 동안 최신 geometry가 여러 번 올 수 있습니다.

COMPLETED

pointer release와 compositor 완료를 거쳐 최종 geometry가 전달됩니다.

GeometryChanged 횟수는 backend마다 다릅니다. 앱은 횟수를 가정하지 않고 항상 최신 geometry를 사용해야 합니다.

09 · PUBLIC API

API 이름보다 먼저 사용 목적 이해하기

일반 앱은 content root와 frame 설정을 주로 사용하고, 제품 wrapper는 command와 typed signal까지 사용합니다.

API 그룹왜 필요한가언제 사용하는가
New(), Attach(), Detach()기존 native window에 frame view tree와 native callback 수명을 연결합니다.window와 option 준비 후 한 번 attach하고, wrapper 종료 시 detach합니다.
DownCast(), handle copyBaseHandle에서 안전하게 타입을 복구하고 동일 WindowFrame 구현을 공유합니다.실패한 DownCast와 기본 생성 handle은 비어 있으므로 instance API를 호출하지 않습니다.
GetContentRoot()앱이 decoration inset을 직접 계산하지 않도록 안정적인 content 전용 부모를 제공합니다.모든 앱 View를 이 root 아래에 추가합니다.
SetDecoration()decoration, layout, style을 원자적으로 검증하고 설치합니다.초기 frame 설치 또는 구조가 바뀌는 동적 테마 교체에 사용합니다.
SetFrameStyle(), ClearDecoration()view 구조를 유지한 style 교체와 decoration/layout 제거를 구분합니다.Style만 바꾸면 전자를, frame slot을 모두 비우면 후자를 사용합니다.
SetDecorationInsets()top, bottom, left, right slot이 frame 안에서 예약할 공간을 layout에 알립니다.border UI의 두께나 header/footer 높이를 정할 때 사용합니다.
RequestFrameResize(), RequestContentResize()shadow를 제외한 frame 기준과 실제 앱 content 기준 크기를 구분합니다.제품 요구가 어느 좌표 공간을 기준으로 하는지 선택해 하나만 사용합니다.
SetMinimumFrameSize(), SetMaximumFrameSize()interactive resize와 native geometry에 적용할 frame 기준 제약을 보관합니다.setter가 false를 반환하면 이전 제약이 유지됩니다. Optional getter의 bool을 먼저 확인합니다.
RequestMinimize(), RequestMaximize(), RequestRestore(), RequestClose()role button과 외부 wrapper가 같은 command 경로를 사용하게 합니다.반환값은 dispatch 결과입니다. 완료를 관찰하는 곳은 command마다 다릅니다. minimize/maximize/restore는 WindowStateChangedSignal(), move/resize는 InteractionChangedSignal()과 geometry signal, close는 CloseCallback입니다.
ToggleMaximize()현재 상태의 반대를 요청합니다.IsMaximized()로 직접 분기하는 것보다 안전합니다. 최소화된 창처럼 토글할 수 없는 상태까지 함께 판단합니다.
CloseCallbackDefault close command가 호출할 앱 소유 종료 정책입니다.WindowFrame은 window를 파괴하거나 앱을 자동 종료하지 않습니다. Callback에서 확인, cleanup, Application::Quit() 등을 수행합니다.
WindowStateChangedSignal(), WindowStatePresentedSignal()상태 확인 시점과 그 상태가 화면에 그려진 시점을 구분합니다.상태 변화 자체는 Changed, 실제 표시 후 처리는 Presented를 사용합니다. 둘 다 compositor 주도 변경에도 발생합니다.
GeometryChangedSignal(), GeometryChangeCompletedSignal()move/resize 중간 geometry와 최종 geometry를 구분합니다.실시간 layout 반응과 저장할 최종 위치/크기를 나눕니다.
Window::FocusChangedSignal()window focus 획득/상실을 알려줍니다.active/inactive decoration 표현이 필요할 때 underlying window에서 직접 관찰합니다.
InteractionChangedSignal(), CommandProcessedSignal()pointer/native interaction lifecycle과 command dispatch 결과를 별도로 관찰합니다.입력 진행 여부와 native 완료 여부를 operation 반환값 하나로 추측하지 않습니다.
SetFeatureEnabled(), IsFeatureEnabled()제품이 제공할 기능을 선언합니다. runtime backend 탐지가 아닙니다.기본값은 모두 true이며 제공하지 않을 기능만 New() 전에 끕니다.
Callback과 signal은 sender-first입니다CommandInterceptor와 모든 WindowFrame signal은 이벤트를 발생시킨 WindowFrame을 첫 번째 인자로 전달합니다. 하나의 policy나 observer를 여러 frame에 연결해도 sender로 발생 대상을 구분할 수 있습니다.

Handle과 attach 수명

생성 전

기본 생성 handle과 실패한 DownCast() 결과는 비어 있습니다. Instance API는 New()로 초기화한 뒤 사용합니다.

Attach

Frame을 window에 parent하고 native callback과 저장된 size constraint를 연결합니다. 이미 attached이면 추가 작업 없이 유지됩니다.

Detach

Interaction과 callback을 끊고 native constraint를 해제하지만 content, decoration, style은 보존합니다. 다음 Attach()에서 다시 연결됩니다.

Handle 복사는 새 window를 만들지 않습니다복사한 WindowFrame은 같은 구현, ContentRoot, frame, signal을 공유합니다. 독립 window가 필요하면 native Window마다 New()를 호출합니다.

SetFrameStyle()GetFrameStyle()은 요청한 style의 복사본입니다. Maximized 상태에 맞춰 해석된 view snapshot은 아닙니다.
SetOverlayEnabled()IsOverlayEnabled()는 요청 policy입니다. Overlay layout은 attached + maximized 상태에서만 적용됩니다.
SetOverlayAutoHideDelay()GetOverlayAutoHideDelay()는 설정값 그대로이며, 0은 auto-hide를 끈 상태를 뜻합니다. 0을 넣으면 auto-hide로 이미 숨겨져 있던 decoration도 다시 나타납니다.
SetInteractiveResizePolicy()GetInteractiveResizePolicy()는 FREE, KEEP_ASPECT_RATIO, DISABLED를 반환합니다. Interactive resize만 제어하며 programmatic size API는 허용합니다.
SetDecorationLayout()설치된 slot view와 그 안의 내용, 앱이 연결한 signal을 유지한 채 inset과 handle 크기만 바꿉니다. SetDecoration()은 view를 교체합니다.
RequestFrameResize() / RequestContentResize()maximized geometry는 compositor 소유이므로 그 상태에서는 false를 반환하고 요청을 받지 않습니다.
상태 조회GetWindowState(), IsMaximized(), IsMinimized()는 window system이 보고한 상태입니다. client가 따로 추정하는 상태는 없습니다.

Resize policy 선택

FREE

두 resize handle을 활성화하고 고정 비율 없이 compositor resize를 요청합니다.

KEEP_ASPECT_RATIO

Handle은 그대로 활성화하며 native surface 비율 유지를 window system에 요청합니다.

DISABLED

진행 중 resize를 취소하고 두 handle을 숨겨 interactive resize를 차단합니다.

windowFrame.SetInteractiveResizePolicy(
  WindowFrameInteractiveResizePolicy::KEEP_ASPECT_RATIO);
Tizen native 연결KEEP_ASPECT_RATIO는 wm.policy.win.resize_aspect_ratio=1 auxiliary hint를 사용합니다. 비율 유지 정책을 적용할 때 기존 hint 값을 보관하고, policy가 FREE 또는 DISABLED로 바뀌거나 detach될 때 원래 값을 복원합니다. 기본 FREE policy는 앱이 소유한 hint를 변경하지 않습니다. Backend가 hint를 거부하면 handle resize는 자유 비율로 계속 동작할 수 있습니다.
Surface 비율과 content 비율은 다를 수 있습니다Compositor는 client shadow outset을 포함한 native surface 비율을 유지합니다. Visible frame의 정확한 비율이 필요하면 client-shadow outset을 0으로 두거나 system shadow를 사용합니다.

상태/API정확한 의미
STARTEDMove/resize request를 발행하고 interaction tracking을 시작했습니다.

Resize direction API가 따로 있는 이유

GetResizeDirection(out)

방향이 있으면 true와 값을 반환하고, 없으면 false이며 out 값을 바꾸지 않습니다. Feature 활성화나 native 완료 여부를 뜻하지 않습니다.

Resize metadata

bottom-left와 bottom-right 중 어느 handle에서 요청됐는지 wrapper에 전달합니다. 별도의 Has API나 assert precondition이 필요하지 않습니다.

WindowFrameCommandDisposition OnCommand(
  WindowFrame sender,
  const WindowFrameCommandRequest& request)
{
  WindowResizeDirection direction;
  if(request.GetResizeDirection(direction))
  {
    BeforeProductResize(direction);
  }

  // WindowFrame이 같은 방향으로 기본 native resize를 계속 요청합니다.
  return WindowFrameCommandDisposition::CONTINUE_DEFAULT;
}
이 getter가 resize를 실행하지는 않습니다GetResizeDirection(direction)은 request metadata를 읽을 뿐입니다. 자체 native resize를 시작한 경우에만 HANDLED을 반환하고, 단순 로깅이나 선행 UI 작업이면 CONTINUE_DEFAULT을 반환합니다.
10 · PRODUCT WRAPPER

제품용 DesktopWindow는 composition으로

샘플의 WindowFrameExample은 학습용입니다. 제품은 WindowFrame을 멤버로 가진 wrapper에서 factory와 typed hook을 공개하는 편이 단순하고 ABI 부담도 작습니다.

Virtual factories

CreateDecoration(), CreateFrameStyle(), CreateOptions()로 제품별 모양을 교체합니다.

Typed hooks

OnCommand, maximize/restore용 OnStatePresented, OnGeometryCompleted 등 필요한 지점만 override합니다.

Forwarding API

Maximize(), Restore(), Minimize(), Close(), GetContentRoot()를 앱 친화적으로 노출합니다.

권장 wrapper 골격 
class DesktopWindow : public Dali::ConnectionTracker
{

protected:
  virtual Dali::Ui::WindowFrameDecoration CreateDecoration(
    Dali::Ui::WindowFrameLayout& layout) = 0;

  virtual Dali::Ui::WindowFrameOptions CreateOptions();
  virtual void ConfigureWindowFrame(Dali::Ui::WindowFrame& windowFrame) {}

12 · SHIP CHECKLIST

제품 적용 전 확인

API 사용 계약과 compositor 경계를 마지막으로 점검합니다.

  • native Window가 transparent로 구성되어 있다.
  • 앱 UI는 GetContentRoot()에만 추가한다.
  • slot root는 설치 전에 unparented 상태이거나, 이 WindowFrame에 이미 설치된 slot이다.
  • command role은 decoration slot 내부에 있다.
  • role control에 앱 click callback을 중복 연결하지 않는다.
  • SetDecoration() 결과를 검사한다.
  • frame 크기와 content 크기의 기준을 구분한다.
  • decoration 교체 size policy를 의도적으로 선택한다.
  • 일반 restore geometry를 앱이 덮어쓰지 않는다.
  • dispatch 완료와 compositor 완료를 구분한다.
  • presented signal과 state signal의 타이밍 차이를 확인한다.
  • interceptor에서 동일 request API를 재호출하지 않는다.
  • overlay auto-hide 후 mouse/touch 재표시를 검증한다.
  • 양쪽 handle에서 KEEP_ASPECT_RATIO native surface 비율 유지를 검증한다.
  • KEEP_ASPECT_RATIO에서 FREE로 바꾼 뒤 자유 비율 resize를 검증한다.
  • N-patch/View shadow와 corner clipping을 실기기에서 확인한다.
  • DefaultWindowDecoration를 쓴다면 handle을 멤버로 들고 있고, shadow를 켠 창은 투명하게 만들었다.
  • 아이콘이 실기기에서 보인다. 컴포넌트 이미지가 <dataReadOnlyDir>/ui/images/components/border/에 설치되어 있다.
  • 이동을 시작할 때 CANCELLED가 먼저 오지 않는다. compositor grab이 focus를 가져가는 backend에서 확인한다.

01 / DALi UI

DALi UI#

DALi 기반 애플리케이션을 위한 Native UI Framework

DALi UI는 애플리케이션이 Native 환경에서 화면을 구성하고 운영하는 데 필요한 공통 UI 기능을 제공합니다. View와 Layout을 기반으로 상태와 이벤트, 화면 이동, Theme, Text, Scroll과 Focus까지 하나의 Framework 범위로 구성했습니다.

REPORT SCOPE

Native 앱에 필요한 UI 기능

Native 앱이 제품 화면을 구성하려면 성능 경로뿐 아니라 그 위에서 사용할 충분한 UI 기능이 필요합니다. DALi UI는 화면마다 공통 기능을 다시 구현해야 하는 부담을 줄이고, 애플리케이션이 DALi 위에서 제품 수준의 UI를 구성할 수 있게 합니다.

적용 애플리케이션에서는 NUI 기반 구성과 비교해 메모리 사용량과 런칭 성능이 개선되었습니다. 개선 폭은 앱 구성과 측정 조건에 따라 달라질 수 있습니다.

04 / View State & Interaction

View State & Interaction#

Focused, pressed, hovered 등의 상태를 View 단위의 공통 모델로 관리합니다. 이 상태와 touch, key, accessibility 입력을 바탕으로 click과 long press처럼 UI 맥락이 담긴 interaction을 제공하므로, 앱이 화면마다 상태 전환과 입력 판정을 다시 구현할 필요가 없습니다.

읽기 편의에 맞춘 Text 크기

System font scale을 반영하되 화면 설계가 무너지지 않도록 최소·최대 배율을 정할 수 있습니다. 변경된 text 크기에 맞춰 줄바꿈과 주변 layout도 다시 계산합니다.

번역 가능한 모든 문구

일반 문자열과 단수·복수 표현을 지원합니다. Label뿐 아니라 입력창 placeholder, 접근성 name과 description도 언어 변경에 맞춰 갱신됩니다.

언어에 맞는 읽기 방향

부모 설정, text 내용 또는 현재 locale을 기준으로 LTR과 RTL 방향을 선택합니다. 언어가 바뀌면 text 정렬과 layout 방향이 함께 맞춰집니다.

화면별 적용 범위 제어

고정 크기가 필요한 View는 system scale 적용에서 제외할 수 있고, 특정 문자열은 자동 번역 대신 앱이 지정한 표현을 유지할 수 있습니다.

09 / Navigator

Navigator#

Navigator는 화면을 page와 modal이라는 공식 단위로 관리해 UIFW가 현재 화면의 경계와 앱의 이동 의도를 알 수 있게 합니다. 화면 전환에 맞춰 back, lifecycle과 transition뿐 아니라 focus의 진입과 복원, accessibility 노출 범위와 background 화면의 입력 상태를 함께 조정합니다.

활성 화면과 입력 범위

최상위 page 또는 modal을 현재 화면으로 구분합니다. 뒤에 가려진 화면의 touch와 key 입력을 차단해 사용자 입력이 활성 화면에만 전달되도록 합니다.

Focus 진입과 복원

새 화면이 나타나면 적절한 첫 focus 대상으로 진입하고, 화면을 닫으면 이전 화면에서 마지막으로 사용한 위치로 돌아갑니다. Modal이 열린 동안에는 focus 이동도 그 안에 머뭅니다.

Accessibility 화면 전환

현재 page와 modal만 screen reader의 탐색 범위에 포함합니다. 화면이 바뀌면 새 화면의 의미와 제목을 알리고 가려진 content는 탐색에서 제외합니다.

Back · lifecycle · transition

Back은 열린 modal을 먼저 닫고 이후 page stack을 되돌립니다. 화면의 등장과 퇴장, lifecycle event와 transition을 같은 navigation 상태에 맞춰 처리합니다.

10 / Enhanced Focus System

Enhanced Focus System#

리모컨이나 키보드로 조작하는 화면에서는 focus가 단순히 가까운 View가 아니라 UI 구조와 사용 흐름에 맞는 대상으로 이동해야 합니다. DALi UI는 Android 계열 UIFW에서 익숙한 자식 우선 focus 요청, 방향별 이웃, 영역 단위 탐색과 공간 기반 후보 검색을 View tree에 맞게 제공합니다.

10
01 · Entry복합 View의 첫 focus

Container에 focus를 요청하면 내부에서 가장 적절한 child를 선택합니다. 화면 진입 시 앱이 내부 구조를 직접 탐색할 필요가 없습니다.

02 · Direction명시적 이웃 + 공간 탐색

제품이 지정한 방향별 이웃을 우선 사용하고, 별도 지정이 없으면 위치와 거리를 기준으로 자연스러운 다음 대상을 찾습니다.

03 · Local rule영역별 이동 규칙

List, menu, carousel처럼 고유한 이동 방식이 필요한 영역은 자체 규칙을 가질 수 있고, 앱은 첫 focus와 공통 예외 규칙을 정할 수 있습니다.

04 · BoundaryFocus group과 탐색 제외

Modal이나 panel 안에 이동을 머물게 하고, 장식용 subtree처럼 focus 대상이 없는 영역은 검색에서 제외할 수 있습니다.

05 · IndicationFocus와 표시의 분리

논리적 focus는 유지하면서 indicator만 숨길 수 있습니다. Touch, pointer, remote가 전환되어도 입력 대상과 시각 표현을 따로 제어합니다.

06 · ContinuityScroll과 Window 연속성

Focus된 항목이 viewport에 보이도록 scroll하고, 여러 Window와 입력 장치가 있는 환경에서도 이동이 시작된 화면의 맥락을 유지합니다.

12 / Scroller

Scroller#

Scroller는 touch, key와 focus 이동에서 content가 예측 가능한 위치에 표시되도록 관리합니다. 리모컨이나 키보드로 탐색할 때 focus 대상이 viewport 밖에 남지 않도록 scroll과 focus를 함께 처리합니다.

12
FOCUSED CHILD / MAKE VISIBLE

Focus-aware scrolling

SetScrollOnFocus와 MakeVisible, Start, Center, End target policy를 제공합니다. Peek distance도 설정할 수 있습니다.

입력별 제어

Key scroll step과 enable 설정을 제공합니다. Pan 입력과 programmatic scroll은 별도로 제어하며 방향은 Vertical, Horizontal, Both 중에서 선택합니다.

Edge & scrollbar policy

Never, Always, ContentScrolls overscroll policy와 start/end EdgeEffect를 제공합니다. Scrollbar는 Auto, Always, Never로 설정합니다.

Scroll signal과 API

Scroll과 drag의 시작, 진행, 완료 signal을 제공합니다. Position, child, X/Y 값을 사용해 ScrollTo를 호출할 수 있습니다.

Chart#
